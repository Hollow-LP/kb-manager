# 业务演示脚本（DEMO）

本演示按验收标准逐条走一遍。**代码运行在开发机**（后端 :8000、前端 :5173），**VM 192.168.100.66 只承载依赖**（PostgreSQL、Redis 容器）。

## 0. 演示前准备

```bash
# 1) VM 依赖（若之前被其他项目占用端口，先停掉那些容器）
ssh root@192.168.100.66 "cd /opt/kb-manager/deploy && docker compose up -d"
ssh root@192.168.100.66 "docker ps --filter name=kb- --format '{{.Names}} {{.Status}}'"
#   kb-postgres  healthy（5432）   kb-redis  healthy（6379）

# 2) 本机后端与前端（日志写 D 盘）
cd backend && uv run python run.py > D:/kb-manager-work/logs/backend.log 2>&1 &
cd frontend && npm run dev > D:/kb-manager-work/logs/frontend.log 2>&1 &
curl -s http://127.0.0.1:8000/api/health        # {"status":"ok",...}

# 3) （可选）重建演示问答数据，让看板趋势更完整
cd backend && uv run python scripts/rebuild_history.py --keep
```

演示账号（密码统一 `Admin@123`）：

| 账号 | 部门 | 角色 | 用途 |
|---|---|---|---|
| admin | 技术中心 | 系统管理员 | 组织架构、看板 |
| kbadmin | 行政中心 | 知识管理员 | 导入、配权限、FAQ 审核 |
| user_tech | 技术中心 | 普通用户 | 有权访问 IT 规范 / 差旅标准（个人授权） |
| user_fin | 财务中心 | 普通用户 | 可访问财务审批手册 |

## 1. 验收①：登录、角色、部门、菜单/按钮权限

1. 打开 http://localhost:5173 ，用 `admin` 登录 → 进入个人中心，显示部门「技术中心」、角色「系统管理员」。
2. 左侧菜单可以看到：数据看板、知识导入中心、可访问知识库、AI 对话工作台、组织架构（用户/角色/部门）、知识沉淀（FAQ/已发布/缺口）。
3. 退出，用 `user_tech` 登录 → 菜单只剩「AI 对话工作台」「可访问知识库」；直接访问 `/org/users` 显示 **403**。
4. 用 `admin` 进入 **角色管理** → 选中「普通用户」→ 取消勾选「AI 问答访问」→ 保存；再用 `user_tech` 提问 → 接口返回 **403 缺少权限**（权限实时生效，无需重新登录）。演示后勾回并保存。
5. **部门管理**：展示部门树（总公司 → 技术中心 → 研发部/运维部 …），点击「技术中心」右侧显示成员；`admin` 可新增/编辑部门，`user_tech` 看不到该菜单。

## 2. 验收②：单篇与批量导入

1. `kbadmin` 登录 → **知识导入中心**。
2. 单文件：拖入 `backend/seed_docs/年假计算规则.docx` → 「开始导入」→ 进度依次为 解析中 → 向量化 → 成功。
3. 批量：一次选择 `IT安全规范.pdf`、`新员工入职指南.md`、`差旅标准说明.txt` 三个文件 → 开始导入 → 三个任务全部成功。
4. 非法格式（如一张图片）会整批拒绝并提示「不支持的文件格式」。
5. 点击「查看知识单元」跳转详情，看到正文、切片数、来源文件。

## 3. 验收③：知识单元增删改查 + 四类数据权限混合配置

1. **可访问知识库**列表：按编号/标题/正文搜索，按分类、格式、状态筛选，分页。
2. 打开任一单元 → 编辑标题/分类/标签/正文 → 保存；正文变更后提示「已自动重建检索切片」。
3. 点击 **配置数据权限**：
   - 打开「全局公开」开关；
   - 指定部门：勾选「技术中心」；
   - 指定角色：选择「高管」；
   - 指定人员：选择「赵技术」；
   - 底部摘要显示「全局公开 + 1 个部门 + 1 个角色 + 1 名个人」→ 保存并生效，列表显示「4 项权限」。
4. 批量勾选若干单元 → 批量删除；打开「已删除」开关可看到并恢复。

## 4. 验收④：满足任一权限实体即可访问

在权限配置弹窗里把某个单元分别配置为：**仅全局** / **仅部门（技术中心）** / **仅角色（高管）** / **仅个人（user_tech）**，再用 4 个账号在「可访问知识库」核对：

| 单元 | user_tech（技术中心） | user_fin（财务中心） | user_hr | user_vp（高管） |
|---|---|---|---|---|
| 员工报销制度（全局） | ✅ | ✅ | ✅ | ✅ |
| IT安全规范（部门=技术中心） | ✅ | ❌ | ❌ | ❌ |
| 财务审批权限手册（部门=财务中心 + 角色=高管） | ❌ | ✅ | ❌ | ✅ |
| 差旅标准说明（个人=user_tech） | ✅ | ❌ | ❌ | ❌ |
| 无权限配置的测试文档（未配置） | ❌ | ❌ | ❌ | ❌ |

> 说明：部门权限**不向子部门继承**——`user_hr` 属于「人力资源部」，不会因为「行政中心」被授权而获得访问。

## 5. 验收⑤：AI 对话强制鉴权 + 鉴权过滤 + 权限缺失提示

1. `user_tech` 登录 → **AI 对话工作台**。
2. 提问「出差住宿标准是多少？」→ 流式输出回答，下方出现 **引用来源**（差旅标准说明，相似度约 85%+）。
3. 提问「单笔五万元以上的费用需要谁审批？」→ 回答上方出现橙色卡片 **「部分相关知识无权访问」**，列出《财务审批权限手册》等单元，正文不包含该手册内容。
4. 退出，用 `user_fin` 登录，提同一个问题 → 没有缺失提示，回答中给出「财务负责人可审批五万元以内，超过五万元须由总经理审批」。
5. 未登录直接调用接口 `POST /api/ai/chat/stream` → **401**。

## 6. 验收⑥：数据看板

1. `admin` 登录 → **数据看板**。
2. 指标卡：Agent 访问次数、独立访问人数（UV）、知识单元总数、总 Token 消耗、平均响应时间（含 P95）。
3. 榜单：常见问题 TOP（按问句合并变体）、知识单元热度 TOP（引用次数 + 权限拦截次数）。
4. 图表：访问趋势（柱状访问量 + 折线独立人数）、Token 消耗趋势（prompt/completion 堆叠）、响应时间分布直方图 + P50/P95。
5. 切换「近 7 天 / 近 30 天 / 近 90 天」「按日 / 按周」，图表和指标随之变化。

## 7. 验收⑦：FAQ 挖掘 → 审核发布 → 缓存加速

1. 用 `user_tech` 在 AI 工作台就同一个知识库内问题连续提问 3 次（例如「年假有几天？」的不同问法）。
2. `kbadmin` → **FAQ 推荐与审核** → 点击「立即挖掘」→ 出现候选问题（推荐频次 ≥ 3，附同义变体示例）。
3. 点击「通过」→ 在弹窗里编辑标准化答案 → 「确认发布」。
4. **已发布 FAQ 库**：该问题显示「已缓存」「自动挖掘」。
5. 回到 AI 工作台，用同样的问法（标点/空格不同也可以）提问 → 右上角出现 **「FAQ 缓存命中」**，回答即标准答案，耗时明显更短（`done.total_tokens = 0`，未调用模型）。
6. 在 FAQ 库点「编辑」修改答案 → 再次提问即返回新答案；「下架」后再次提问会重新走知识库检索。

## 8. 验收⑧：知识缺口识别

1. 用任一账号提问库外问题，例如「公司今年营业收入是多少？」「公司的股票期权怎么申请？」「公司有几个食堂？」
2. `kbadmin` → **知识缺口** → 点击「重新识别缺口」→ 列表出现这些问题（含提问频次、最近提问时间、样例问法）。
3. 点击「一键建档」→ 弹窗已预填标题和正文模板 → 填写正式内容 → 「创建知识单元」→ 自动跳转到单元编辑页，缺口消失（状态变为已解决）。
4. 在 AI 工作台再问同一问题，即可得到基于新知识单元的回答。

## 附：常见演示异常与处理

| 现象 | 处理 |
|---|---|
| 页面提示「服务未配置问答模型」 | `.env` 中 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 未填写 |
| 回答生成失败 | 检查网络与 Key 余额；日志见 `D:/kb-manager-work/logs/backend.log` |
| 看板数据为空 | 先提问几次，或执行 `scripts/rebuild_history.py` 重建演示数据 |
| 导入任务一直「解析中」 | 首次加载向量模型约需 10~20 秒，稍等后刷新 |
